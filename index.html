[CASE 01 · Data 모니터링 중 발견]

모바일 앱 PV 이상 트래픽 탐지 · 필터링 정책 개선

일상 모니터링에서 지표를 오염시키던 비정상 트래픽을 발견하고, 필터링 정책 설계까지 주도
이상 탐지 · 정책 설계 Databricks
PROBLEM

일상적인 Data 모니터링 중, Databricks 로그에서 Home 특정 섹션의 PV가 1초 이하 간격으로 반복되는 패턴을 발견했습니다. 특정 channel_code에 집중되어 있었고, 유저 1인당 PV가 20–30회까지 발생하는 비정상 트래픽이 지표를 오염시키고 있었습니다.

HYPOTHESES → VERIFIED
H1 · 확인됨잠금화면 상태에서도 PV가 발생하는 구조 — lockscreen=true인데 attached=true인 케이스 규명
H2애드웨어 또는 비정상 자동 실행 가능성
H3앱 크래시 루프에 의한 반복 실행 가능성
DECISION
  • lockscreen=true 상태의 PV 제외 — 기본 필터
  • screenoff 상태에서 1초 내 PV 5회 이상이면 제외 — 확장 필터
  • 앱 크래시 반복 루프에 Safeguard 적용 — 확인 시 프로세스 종료

정상적인 푸시 진입 유저 일부가 제외될 가능성이 있었지만, 데이터 노이즈 제거 효과가 더 크다고 판단하고 정책 적용을 제안했습니다.

[CASE 02 · 데이터 분석 중 발견]

신규 섹션 배치 실험 — 유저 행동 데이터 기반 가설 설계

낮은 PV라는 표면 지표 뒤에서, 탐색 밀도라는 진짜 신호를 찾아 실험으로 연결
가설 수립 · 실험 설계 유저 행동 분석 실험 진행 중
PROBLEM

홈 화면 중간 영역에 런칭한 신규 섹션이 위치적 한계로 초기 PV와 클릭률이 낮았습니다.

INSIGHT

런칭 전후 데이터를 비교해 인접 섹션의 유저 분산을 확인하던 중, 두 가지 신호를 발견했습니다. 섹션의 PV는 낮지만 진입 유저의 탐색 밀도가 인당 평균 5회로 매우 높다는 것, 그리고 유저들이 홈 진입 후 맨 끝 섹션으로 바로 스와이프해 탐색하는 특이 패턴이 있다는 것.

공백기가 아니라 전환기였습니다

Q. 2024–2025, 2년의 공백이 있네요?

좋아하던 반려동물 분야에 제대로 도전한 시간이었습니다. 애견미용사 3급(2024.12)과 2급(2025.08)을 취득하고 미용실 인턴으로 실무까지 경험했습니다.

그 과정에서 확인한 것은 오히려 저의 방향이었습니다. 혼자 완결하는 일보다 여러 직군과 협업해 무언가를 함께 만들어가는 일에서 더 큰 즐거움을 느꼈고, 병행한 AI 스타트업(메이아이)에서 공간 라벨링의 구조를 설계하는 일을 하며 IT 복귀를 확신했습니다.

단순한 복귀가 아니라, QA의 검증을 넘어 제품 전반을 매니징하는 PM으로의 커리어 확장으로 방향을 정했습니다.
