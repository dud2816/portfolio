CASE 01 · DATA 모니터링 중 발견

모바일 앱 PV 이상 트래픽 탐지 · 필터링 정책 개선

일상 모니터링에서 지표를 오염시키던 비정상 트래픽을 발견하고, 필터링 정책 설계까지 주도
PROBLEM

Databricks 로그에서 Home 특정 섹션의 PV가 1초 이하 간격으로 반복되는 패턴을 발견했습니다. 특정 channel_code에 집중되어 있었고, 유저 1인당 PV가 20–30회까지 발생하고 있었습니다.

PV 추이 — 필터링 전후
필터링 전 (이상치 포함) 필터링 후
* 상대 패턴을 재구성한 예시 차트입니다.
HYPOTHESES → VERIFIED
H1 · 확인됨잠금화면 상태에서도 PV 발생 — lockscreen=true인데 attached=true인 케이스 규명
H2애드웨어·비정상 자동 실행 가능성
H3앱 크래시 루프에 의한 반복 실행 가능성
DECISION
  • lockscreen=true 상태의 PV 제외 — 기본 필터
  • screenoff 상태 + 1초 내 PV 5회 이상이면 제외 — 확장 필터
  • 앱 크래시 반복 루프에 Safeguard 적용 — 확인 시 프로세스 종료

정상 푸시 진입 유저 일부가 제외될 가능성보다 노이즈 제거 효과가 크다고 판단해 정책 적용을 제안했습니다.

CASE 02 · 신규 섹션 효율 분석 중 발견

신규 섹션 '새로왔G' 효율 분석 · 위치 변경 실험

"PV가 낮다"는 표면 지표 뒤에서, 높은 탐색 효율이라는 진짜 신호를 찾아 실험으로 연결
PROBLEM

6월 15일 홈 중간 영역에 신규 섹션 '새로왔G'가 런칭됐습니다. 3주간(6.15–7.7)의 데이터를 분석한 결과, PV는 비교한 인접 4개 섹션 중 최하위였습니다.

ANALYSIS ① — 트래픽은 어디서 왔나

런칭 전후 인접 섹션을 비교하니, 새로왔G의 트래픽은 주로 패션 섹션에서 분산된 것이었습니다.

브랜드혜택−10%
패션−36%
런칭 전 대비 PV 변화율 — 패션 유저가 새로왔G로 이동
ANALYSIS ② — 섹션의 진짜 효율

PV는 낮았지만, 일단 진입한 유저의 클릭 전환율은 4개 섹션 중 상위권이었습니다. 등록 상품 188개에 일평균 아이템 클릭이 유의미하게 발생 — 진입 유저는 평균 5개 가까운 상품을 탐색하고 나갔습니다. 콘텐츠 매력도가 아니라 위치가 문제였습니다.

ANALYSIS ③ — 유저는 어디로 가나

맨 끝 섹션(상생마켓)의 PV가 4개 섹션 중 가장 높았는데 클릭 전환율은 가장 낮았습니다. 유저가 홈 진입 후 맨 끝으로 바로 스와이프하는 행동 패턴의 근거 — 트래픽은 몰리지만 소비되지 않는 자리라는 뜻입니다.

섹션별 PV × 클릭 전환율 (상대지수, 최대=100)
* 내부 지표 보호를 위해 상대지수로 변환한 실측 기반 차트입니다.

새로왔G는 전환율은 높은데 트래픽이 없고, 상생마켓(맨 끝)은 트래픽은 많은데 소비되지 않습니다. 두 섹션의 위치를 교환하면 서로의 약점이 상쇄됩니다.

HYPOTHESIS & DESIGN
  • 탐색 효율이 검증된 새로왔G를 맨 끝(상생마켓 자리)으로 이동하면 전환율 상승할 것이라는 가설 수립
  • 기대에 미치지 못할 경우 원위치로 롤백하는 프로세스를 실험 설계에 포함
실험 진행 중

"PV가 낮으니 실패"가 아니라, 데이터로 문제를 재정의해 검증 가능한 실험으로 만든 사례입니다.
